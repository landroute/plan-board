# plan-board（板）

時間軸にタスクを**置く**ための単体Webアプリ。スマホと Surface が同じ URL を開く PWA。

依存ライブラリなし。`index.html` 1枚に CSS と JS を同梱している（day-clock と同じ流儀）。

見た目（配色・文字・タブ・ボタン）は day-clock（`claude-tools/day-clock/day-clock.html`）と揃えている。
明るめダーク / ライトは端末の設定に従う（day-clock は ☀ / ☾ で切り替え）。色を変えるときは両方を同時に直す。

## これは何を解くか

デイリーノートは「ログ」としては正しいが「操作面」としては間違っている。
時間が文章の中の文字列でしかないため、線形的な文章が積み上がるだけで
「対象の時間に何をするか」が読み取れない。

板は**時間軸を板にして、文章を書かずに置く**。カードの高さがそのまま所要分数になる。

## データの流れ（一方通行）

```
板 → plan-data/plan.json → day-clock（Surface）→ Vault デイリーノート（記録）
```

各ストアの書き手は1つだけ。往復させないので衝突しない。

- **このアプリが書くのは `plan-data` だけ**
- `plan-data` は private。板は GitHub API 経由で読み書きする

## セットアップ

1. GitHub で **fine-grained personal access token** を作る
   - Repository access: **`plan-data` のみ**
   - Permissions: **Contents → Read and write**
   - **`claude-tools` には権限を与えないこと**
2. 板を開き、右上の歯車 → リポジトリとトークンを入れて「保存して読み込む」
3. Android: Chrome のメニューから「ホーム画面に追加」

トークンはその端末のブラウザの localStorage にのみ保存される。
端末を紛失したら GitHub 側でトークンを失効させること。

## 操作

| 操作 | 挙動 |
|---|---|
| ブロックの `＋ ここに置く` | 箱 / 型 のシートが開く |
| 型をタップ | 大（プロジェクト）→ 中（工程）→ 小（1手の型）の3タップで選び、補足を任意で1行足して置く（所要分数つき） |
| 箱の中身をタップ | 「未分類」として置く |
| カードをタップ | 完了トグル。完了時刻を記録する |
| 日付タブ | 今日 / 明日 / 明後日 |
| ヘッダの `計画` | プロジェクトの計画を編集する（週次レビュー用）。置くときと同じく **大 → 中 → 小** の順にたどる: プロジェクトを選ぶと工程の一覧（ゴール・期限・週の目標・色は下の「プロジェクトの設定」）、工程を選ぶと期日・完了条件と型（文言と目安分数）。上のパンくずで戻る。保存はどの段からでもでき、プロジェクトごと保存される。工程は**証拠を書かないと完了にできない** |

自由記述だけで置く経路は無い。何を書くか考え始めると止まるので、型を選ぶだけで置けるようにし、
対象（どのシーンか・どの台本か）だけを補足に書く。

余白（バッファ）は**保存していない**。ブロック長 − タスク所要の合計で毎回計算し、
淡色・ラベルなしの帯として描く。埋めるべき空白ではなく、確保済みの余白として見せるため。

## 型の書き方の規約

効き目の本体は UI ではなく型の書き方にある。

- **身体が始められる動作**で書く。「〜を検討」「〜を進める」は禁止
- **量を1に固定**する（1オブジェクト / 1シーン / 1本）
- 迷ったら短い方の分数にする（5分の型は「始めるだけ」の役割）

型と計画の実体は `plan-data/projects.json`（形式は plan-data の README）。
型の id は `大/中/小` の 3 つをつないだもので、`plan.json` のタスクの `preset` に入る。
旧 2 階層の id（`blender/blockout` など）は `aliases` で引く。同じ解決を day-clock の `server.js` も持っている。

## アイコンの再生成

```bash
node tools/make-icons.js
```

`icon.svg` と同じ絵を PNG で吐く（Android の PWA インストールは PNG を要求するため）。
